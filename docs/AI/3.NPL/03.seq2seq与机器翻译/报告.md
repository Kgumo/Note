## 1. 实验背景与任务目标
神经机器翻译（Neural Machine Translation, NMT）已成为现代翻译系统的主流范式。本实验旨在基于 NIST 提供的中英平行语料数据，构建并训练一个 Seq2Seq 模型，实现将中文文本翻译为英文文本的功能。
为了获得更好的翻译性能并满足高阶实验要求，本实验在基础的 Encoder-Decoder 框架上进行了多项核心技术改进，包括引入**中文分词**、**使用双向 GRU**、**加入注意力机制**（Attention）、**采用集束搜索**（Beam Search）解码以及使用 **BLEU 指标**进行量化评估。

---
## 2. 数据预处理与改进 (Data Preprocessing)
针对原始数据的特点，本实验在数据处理阶段进行了以下两项关键改进，以提升模型的语义理解能力和泛化能力。
### 2.1 引入 Jieba 中文分词 (Word Segmentation)
- **原问题**：基础代码采用字符级（Character-level）处理，将每个汉字视为一个 Token。这种方式破坏了中文词汇的语义完整性（例如“机器”被拆分为“机”和“器”），导致模型难以捕捉词级语义。
- **改进方案**：引入 `jieba` 分词库对源语言（中文）进行切分。
- **效果**：通过将输入序列转换为词序列（Word-level），显著降低了序列长度，并提升了 Encoder 对中文语义特征的提取效率。
### 2.2 数据集科学划分 (Train/Validation Split)
- **原问题**：直接在全部数据上进行训练无法监控模型的过拟合情况。
- **改进方案**：将预处理后的数据按 **8:2** 的比例随机划分为**训练集**和**验证集**。
- **意义**：在训练过程中，利用验证集评估模型性能，确保模型不仅仅是记住了训练数据，而是具备了泛化能力。

## 3. 模型架构设计 (Model Architecture)
本实验构建了一个增强型的 Seq2Seq 模型，具体架构如下：
### 3.1 编码器：双向 GRU (Bi-directional GRU)
- **基础模型缺陷**：单向 RNN 只能捕捉当前时刻之前的历史信息，无法利用后文语境。
- **改进实现**：使用 `bidirectional=True` 的 GRU（Gated Recurrent Unit）作为编码器。
- **机制**：Bi-GRU 包含前向和后向两个 RNN，分别从两个方向读取输入序列。最终的输出是将两个方向的 Hidden States 进行融合（Concatenation/Sum），从而获得包含了完整上下文信息的语义表示。
### 3.2 解码器：注意力机制 (Attention Mechanism)
- **基础模型缺陷**：传统 Seq2Seq 依赖一个固定长度的 Context Vector 传递信息，在处理长句子时会出现信息瓶颈（Information Bottleneck）和遗忘问题。
- **改进实现**：在解码器中引入 **Bahdanau Attention** 机制。
- **机制**：解码器在生成每一个英文单词时，都会计算当前隐藏状态与编码器所有时间步输出的**权重（Attention Weights）**。这使得模型能够动态地“关注”源句子中与当前翻译最相关的部分（Alignment），有效解决了长句翻译难题。

## 4. 训练策略与超参数调优 (Training Strategy)
为了在有限的算力和时间内获得最佳效果，本实验对训练过程进行了精细化调整。
### 4.1 超参数设置
|参数|数值|说明|
|:--|:--|:--|
|**Hidden Size**|256|平衡模型容量与训练速度|
|**Batch Size**|1|随机梯度下降 (SGD) 模式|
|**Learning Rate**|0.001|初始学习率|
|**Dropout**|0.3|增加正则化，防止过拟合|
|**Epochs**|3|全量遍历训练，确保收敛|
### 4.2 优化策略
1. **全量 Epoch 训练**：放弃随机采样，改为按轮次完整遍历训练集，确保模型覆盖所有样本。
2. **动态学习率衰减 (LR Scheduler)**：采用 `StepLR` 策略，在训练进行到第 2 轮结束时将学习率减半。这使得模型在初期能快速下降，在后期能精细收敛，避免在最优解附近震荡。
3. **梯度裁剪 (Gradient Clipping)**：设置阈值为 5.0，防止因梯度爆炸导致的训练不稳定。
4. **Teacher Forcing**：以 50% 的概率使用真实标签作为解码器的下一步输入，加速模型收敛。

## 5. 解码与评估方法 (Decoding & Evaluation)
### 5.1 解码算法：集束搜索 (Beam Search)
- **方法**：在生成翻译结果时，不再使用贪婪搜索（每次只选概率最大的 1 个词），而是采用 **Beam Search**。
- **配置**：设置 **Beam Width = 3**。模型在每一步解码时保留 3 条累计概率最高的候选路径，最终选择最优的一条。
- **优势**：显著提升了生成句子的连贯性和语法正确性，避免了局部最优解。
### 5.2 评价指标：BLEU Score
- **工具**：使用 `nltk.translate.bleu_score`。
- **方法**：计算模型生成的译文与参考译文之间的 n-gram 重合度（BLEU-4），作为衡量翻译质量的客观标准。

## 7. 实验总结与反思 (Conclusion & Discussion)
### 7.1 调优心得
在实验过程中，我发现 **Learning Rate Scheduler** 和 **Beam Search** 对最终效果影响显著。
- 未加 Scheduler 时，Loss 在后期容易震荡，导致 BLEU 分数无法提升。
- 使用 Beam Search (k=3) 相比 Greedy Search，生成的句子在语法结构上更加完整，重复词现象明显减少。
### 7.2 对 Transformer 的尝试与分析
在实验初期，我曾尝试使用 Transformer 架构（Self-Attention）。但在当前小规模数据集（NIST子集）和单样本训练（Batch Size=1）的限制下，Transformer 出现了严重的欠拟合现象。这验证了 Transformer 架构虽然强大，但对数据量和 Batch Size 有较高要求。因此，最终确定的 **Bi-GRU + Attention** 是针对当前实验环境的最优解。
