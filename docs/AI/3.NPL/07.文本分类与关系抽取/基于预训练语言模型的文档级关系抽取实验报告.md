## 1. 摘要
本实验旨在探究预训练语言模型（BERT与RoBERTa）在文档级关系抽取任务（DocRED）中的性能差异。实验首先基于 BERT-base 实现了基线模型，验证了数据规模对性能的决定性影响（10% vs 100% 数据）。随后，实验通过改进预训练底座为 RoBERTa-base，显著提升了模型对长文本语境的建模能力。最终，RoBERTa 模型在 Codalab 官方测试集上取得了 **F1 = 56.20%** 的成绩，优于 BERT 基线的表现，验证了该方法的有效性。

## 2. 代码实现原理与关键问题解答
本章深入解析了 `gen_data.py` 与 `Config.py` 中的核心逻辑，针对代码中标识的 21 个关键问题（Questions）进行了详细阐述。这些问题涵盖了从数据清洗、特征映射、显存优化到模型评估的全流程。

### 2.1 数据预处理与实体映射 (gen_data.py)

**Q1: `label['in_annotated_train'] = False` ... `fact_in_annotated_train` 代表什么？**  
**答：** 它是一个集合，记录了训练集中所有正样本（存在关系）的三元组 `(head, tail, relation)`。用于后续计算 `Ignore F1` 指标时，排除掉训练集中已经见过的事实，专注于评估模型对新事实的泛化能力。

**Q2: 这里的 `na_triple` 代表什么？**  
**答：** 代表负样本（Negative Samples）。在文档中，任意两个未被标注关系的实体对构成一个 `NA` 三元组。这是关系抽取中数量最大的一类数据。

**Q3: 这里的 `bert_starts_ends` 代表什么？**  
**答：** 记录了原始文本中每个单词（或实体 Mention）在 BERT Tokenizer 切分后对应的 Subword 的起始和结束索引，用于将 BERT 的 Token 向量映射回原词。

**Q4: `token_start_idxs` 的公式中为什么要加 1？**  
**答：** 因为 BERT 的输入序列第一个 Token 是特殊的 `[CLS]` 符号，所以实际文本内容的索引需要向后偏移 1 位。

**Q5: 为什么要把 `token_start_idxs >= max_seq_length-1` 的都置为 `max_seq_length - 1`？**  
**答：** 这是为了处理长文本截断。防止因索引超出最大序列长度（512）而导致程序报错，将越界的索引统一指向序列末尾

### 2.2 模型输入配置与显存优化 (Config.py - Data Loading)

**Q6: `data_train_bert_mask` 代表什么？**  
**答：** BERT 的 Attention Mask。值为 1 代表真实 Token，0 代表 Padding，用于告诉模型在计算 Attention 时忽略填充部分。

**Q7: 这里的 `neg_multiple` (默认3) 代表什么？**  
**答：** 负采样倍率。为了解决正负样本极度不平衡的问题，训练时每个正样本只随机搭配 3 个负样本参与计算。

**Q8: 为什么要设置一个 `h_t_limit` (默认1800)？**  
**答：** 显存保护机制。限制单个 Batch 中处理的最大实体对数量（如 1800），防止因某些文档实体过多导致显存溢出

**Q9: 这里的 `self.dis2idx` 代表什么？**  
**答：** 相对距离的离散化映射表。将实体间的相对距离（如 1, 2, 3-4, 5-8...）映射为离散的类别 ID，用于生成距离 Embedding。

### 2.3 特征构建与动态批处理 (Config.py - Batch Processing)

**Q10: `h_mapping` 和 `t_mapping` 有什么区别？**  
**答：** 这两个变量分别定义了**头实体 (Head Entity)** 和 **尾实体 (Tail Entity)** 的特征提取掩码。在关系抽取中，我们需要分别获得两个实体的向量表示来判断它们之间的关系。`h_mapping` 在头实体出现的所有 Token 位置标记为非零值，`t_mapping` 则标记尾实体的位置。模型利用这两个映射矩阵，通过矩阵乘法从 BERT 的输出序列中高效地“汇聚”（Pool）出对应的实体向量。

**Q11: `max_h_t_cnt` 有什么作用？（以及 `get_train_batch` 中的同名问题）**  
**答：** 动态 Padding。记录当前 Batch 中实体对数量的最大值，将 Tensor 填充到此长度而非固定长度，以节省计算资源。

**Q12: 本代码是如何处理 token 数量大于 512 的文档的？**  
**答：** 直接截断。如果实体的位置超出了 512 个 Token 的范围，该实体及其构成的关系将被丢弃，不参与计算。

**Q13: 为什么要先除以 `len(hlist)`，再除以 `(h[1] - h[0])`？**  
**答：** 这是 Mean Pooling（平均池化）操作。先对一个 Mention 内的所有 Subword 取平均，再对一个实体对应的所有 Mentions 取平均，得到实体的最终向量。

**Q14: `relation_mask` 的作用是什么？**  
**答：** 用于在计算 Loss 时屏蔽掉填充（Padding）产生的虚拟实体对，确保它们不影响梯度更新。
**Q15`get_train_batch` 中的 `max_h_t_cnt` 代表什么？**
**答：** 代表当前 Batch 中“正样本数 + 采样后的负样本数”的最大值，决定了输入到分类器的 Tensor 维度。
### 2.4 训练策略与评估指标 (Config.py - Training & Evaluation)

**Q16: 这里可以使用 cross-entropy loss 吗？**  
**答：** 不建议直接使用标准 Cross Entropy。因为这是多标签分类任务，应使用 `BCEWithLogitsLoss`对每种关系独立预测。

**Q17: 这里的 `NA acc` / `not NA acc` / `tot acc` 分别代表什么？是如何计算的？**  
**答：** 分别代表：负样本预测准确率、正样本预测准确率、整体准确率。用于监控模型是否在单纯“猜”所有样本为无关系

**Q18: 这里是否可以改成 softmax 函数？**  
**答：** 不可以。因为是多标签分类，Softmax 会强制概率和为 1（互斥），而 Sigmoid 允许对每种关系独立打分。

**Q19/Q20/Q21: 这里的 Theta / F1 / AUC 以及 input_theta 分别代表什么？**  
**答：** 这些是关系抽取任务的核心评估指标：
- **Theta (input_theta)**：分类阈值。由于使用 Sigmoid 输出概率，我们需要一个截断值来判定正负例。在验证阶段，代码会遍历不同的阈值，寻找能使 F1 值最大的那个作为最佳阈值（Theta）。在测试阶段，则直接使用这个学习到的 `input_theta`。
- **F1**：Precision和 Recall的调和平均数，是平衡模型查准与查全能力的综合指标。
- **AUC**：P-R 曲线下的面积。它不依赖于具体的阈值选取，能反映模型在所有可能的阈值设定下的整体排序能力和预测质量。代码分别计算了包含 NA 类和忽略 NA 类（Ignore ma_f1）的多种变体，以全方位评估模型性能。

## 3. 实验设置 (Experimental Setup)

- **数据集**：DocRED (Document-Level Relation Extraction Dataset)
- **模型对比**：
    1. **Baseline**: BERT-base-cased
    2. **Ours**: RoBERTa-base
- **数据量设置**：10% (Low Resource) vs 100% (Full Data)
- **关键参数**：Batch Size=4 (Grad Accumulation=8), Learning Rate=3e-5 (RoBERTa)/5e-5 (BERT), Epochs=50。

### 4.2 结果分析

1. **数据规模的影响 (10% vs 100%)**：  
    从结果 ID 3 和 ID 4 可以看出，使用全量数据将 F1 分数从 0.41 提升至 0.54 (+13.3%)。这表明文档级关系抽取是一个数据密集型任务，模型需要大量上下文样本来学习跨句推理模式。
2. **模型架构的改进 (BERT vs RoBERTa)**：  
    从结果 ID 4 和 ID 6 可以看出，在同等全量数据下，**RoBERTa-base (0.5620)** 相比 **BERT-base (0.5446)** 取得了 **+1.74%** 的显著提升。
    - **原因分析**：RoBERTa 移除了 Next Sentence Prediction (NSP) 任务，使用了更大的 Batch Size 和动态掩码训练，这使得它在处理长文档（Long Context）时的语义表征能力更强，更适合 DocRED 这种需要综合全篇信息的任务。
    ![[comparison_curve.png]]
	    该图展示的是BERT-base 与 RoBERTa-base 在验证集上的 F1 分数随训练轮次的变化曲线（每5轮展示一次结果）
	    **快速学习期 (Epoch 0-10)**：两个模型在训练初期均能快速从数据中提取特征，性能迅速攀升至 0.50 左右，表明模型有效地学习到了基础的关系抽取模式。
		**胶着震荡期 (Epoch 10-30)**：在此阶段，两者性能交替上升，RoBERTa 并未立即展现出明显优势，甚至在部分轮次略低于 BERT。这主要归因于 RoBERTa 拥有更大的词表（50k vs 30k）和参数空间，往往需要更多的训练步数来进行预热（Warmup）和拟合。
	    **性能分化期 (Epoch 35-50)**：这是最关键的阶段。随着训练深入，BERT 模型（蓝线）的性能增长逐渐趋缓并开始进入平台期（Plateau）。相比之下，RoBERTa 模型（红线）展现出了更强的后劲与鲁棒性，在 Epoch 34 后实现反超并持续拉开差距。最终，RoBERTa 曲线收敛于更高的 F1 分数（0.5597），明显高于 BERT 的最终结果（0.5475）。
	    该曲线有力地证明了 RoBERTa 在长周期训练下的优越性，其动态掩码机制和去 NSP 任务的设计使其更能捕捉文档级上下文中的细微语义差异，从而突破了 BERT 的性能瓶颈。
3. **最终结论**：  
    通过更换预训练底座为 RoBERTa 并使用全量数据训练，本实验成功构建了一个高性能的关系抽取系统，在官方测试集上达到了 **56.20%** 的 F1 分数，超越了标准的 BERT 基线。

## 5. 总结 (Conclusion)

本实验通过代码填空与模型训练，深入理解了文档级关系抽取中的输入构建、动态 Padding 及多标签损失计算等核心机制。实验结果强有力地证明了：
- (1) 数据量的增加对性能提升至关重要；
- (2) RoBERTa 模型在长文本理解任务上具有优于 BERT 的鲁棒性。未来的工作可以尝试引入外部知识图谱或使用 Large 版本模型以进一步提升效果。
